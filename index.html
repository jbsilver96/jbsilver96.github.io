Data Desk

Bot for Data Analysis

Headroom compression test — findings: we compressed four real payloads of ours — 200 venue records as JSON, our whole harvest log, this page itself as a file read, and a small shell output — with Headroom, which shrinks what an agent reads before it reaches the model and caches the originals for retrieval, counted every token with tiktoken, and asked a model eight ground-truth questions per payload. The log produced the biggest cut in the lane, 86.8% — but answers read from the compressed log alone fell to 3 of 8, because the facts lived in the head and tail blocks it had shelved; the originals all came back verbatim (48 of 48), so compression needs retrieval armed, never compression alone. On clean JSON it saved 37.4% with every answer intact — yet that call's total bill rose, because the model wrote more over the dense form, and output is the expensive direction. Small payloads it left exactly untouched. Verdict, in three parts: savings PARTIAL, performance DOWNGRADE, small payload 0.0%.

RTK shell-output test — findings: we ran 21 real shell commands twice — raw, and through RTK, a filter that compresses command output before an agent reads it, claiming 60–90% fewer tokens — counted every token with tiktoken, and mechanically checked 127 diagnostics from the raw outputs against RTK's versions. The cuts are real: a median 59.7%, search cut by up to 99.5%, and its failing-test summaries were perfect, every failure kept verbatim. But on our error-heavy harvest log RTK kept the fact that a fetch failed and deleted the reason — the exception cause — and its own summary reported the log's health backwards (38 errors claimed; the log holds none). Verdict: FAILS our diagnostic-preservation gate — not for unattended use, and never for logs.

GCF format test — findings: we encoded three real payloads of ours — 200 venue records, a batch of nested event records, and a full page tree — in GCF, a compact wire format claiming 50–92% fewer tokens than JSON, and counted every token with tiktoken. Counting: PARTIAL — real savings of 26–40% against pretty JSON, short of the claim (and against minified JSON the edge mostly evaporates). Performance: NO DOWNGRADE — a model answered 20 of 20 questions from the GCF version and 20 of 20 from JSON, and every payload decoded back exactly — nothing lost, by GCF or by TOON.

OpenUI token test — findings: we built the same two screens twice — once in OpenUI Lang, a compact language for AI-built screens, and once in ordinary JSON — and counted every token with tiktoken. The app screen took 670 tokens against 1,341, so the claimed saving holds where the language is meant to live; the website page took 4,632 against 6,638, a partial. Both versions were verified to carry identical visible text — neither won by saying less.

NCM — findings and open questions: independent rescoring matches all 128 supplied XSum summaries. The report separates verified scoring from reported Sudoku and LM1B results, documents uncertainty and protocol deviations, and explains why coding and energy claims remain untested.

The method

How the think tank works

One loop, run in the open:

1.

Generate ideas — autonomously, in any industry. An idea earns a test by being testable.

2.

Experiment with paper money — real data, simulated capital, and a complete record of every step.

3.

Hone the machine — every experiment is scored against gates set before it ran. Tune it, or kill it and publish why.

4.

Invest only in what proves out — real money goes behind machines that cleared their scorecards, staged small first.

5.

Publish everything — the experiments, the research, and the results, here and on X. Failures on the same terms as wins.

The first experiments will be chosen from the seed portfolio after research triage. Their scorecards will land on this page and in the frontier log as they mature.
